## Lib rules
- Technician month continuity uses SECURITY INVOKER inicializar_tecnicos_mes for entirely empty unlocked months, copying the immediately preceding roster/groups/targets with zero production; copiar_metas_tecnicos updates only existing targets. Goals sub-tabs reuse existing editors and separate data sources.
- Agregados catalogue (`ITENS`) and parser live in `src/lib/agregados.ts`; add items there. User codes in `agg_codes` override defaults.
- Agregados import replaces only the item group in the report, from month start for cumulative ranking reports (total on last day) or per sale day for item lists, so re-imports never double-count.
- System codes are matched ignoring spaces and case (`normCod`); code lists are split only on comma/semicolon/newline because some codes contain spaces.
- Main sales Excel/paste parsing lives in `src/lib/sales-report.ts` and the import UI in `SalesImport`; match seller login before full name to preserve existing consultant identities.
- Seller aliases live in `nomeVendedor` (`src/lib/sales-report.ts`); parts margin stored in R$, % always derived as margem ÷ peças.
- Open-order import keeps only `TIPOS_OK` types and applies seller aliases.
- Agendamento reports (D+1/D0) are recognised by content in `src/lib/agendamento.ts` (D+1 when period date > print date) and stored as rows `mes = "agenda-AAAA-MM"` in `oficina_mes.diario` keyed `tipo:data`, because migrations could not be created in this environment; move to a dedicated table when possible.

- Executive PDF report: analysis rules in `src/lib/relatorio-executivo.ts` (pure, tested) and jsPDF drawing in `relatorio-executivo-pdf.ts`, dynamically imported from `RelatorioExecutivo` in the Cockpit; it reuses Dashboard-computed values, never lets text invent numbers, and keeps a fixed 4-page layout (overflow trimmed, not paginated) so the closing/signature page always exists.
- Passagens: lines with empty Produtivo inherit the technician of the same O.S.; importing Passagens auto-closes matching active Controle O.S. items (`osFaturadasAtivas` → `__encerrado` with `auto: true`) because billed O.S. are finished.
- Oficina bell (Marcos/Delmir) reads only SECURITY DEFINER RPCs (`painel_oficina`, `oficina_agenda_alertas`, `meu_nps`) since data_owner() is NULL for them.
- Sininho/avisos: `src/lib/aviso-aparelho.ts` sets the app badge and native notifications without a service worker, deduping ids in localStorage.
- First-access guide and release notes live in `src/lib/guia.ts` (bump `NOVIDADES` version per release); seen state is per email in localStorage.
- Working days use `src/lib/dias-uteis.ts` (Sat 0.5, national holidays 0) stored in month_params `*_dec` columns (int columns are rounded copies read by restricted RPCs); edits save only via the explicit button and daily auto-advance adds only new days to preserve manual adjustments.
- Unified importer distributes one file to every tab it can feed (`destinos` preview); "O.S. Fechadas" yields technician M.O./peças via `tecnicosDoFatServicos` (no Produtivo = "sem apontamento", matching DMS) and must never be classified as O.S. Abertas (closed-date check in `ehOsAbertas`); daily sales merge by source with `mesclarFat` so services and parts imports never erase each other.
- "O.S. Fechadas" also feeds service agregados via `agregadosDoFatServicos` (`src/lib/agregados-os.ts`, matched by TMO code only, 1 unit per line, value = Serv. Líquido), replacing those items from month start to the report end.
- Acessórios & Estética: rules (Chase catalogue, commission tiers, conciliation) in `src/lib/acessorios-estetica.ts` (tested); sales in `vendas_complementares`, sellers in `vendedores_showroom`, monthly vehicle counts in `rvd_volumes_mes` stored as absolute values (upsert, never summed) so two editors never double-count; projection = DMS department billing + non-billed launches.
- Restricted roles 'acessorios'/'estetica' (Geovana/Marcela): data_owner() is NULL; they reach only their own department rows via `dep_owner()`/`meu_dep()` policies and read DMS totals/O.S. status via SECURITY DEFINER `dep_painel`. Duplicate reviewer (`possiveisDuplicadas`, `diferencaRvd`) imports only the RVD remainder above manual launches.
- Commissions: rules in `src/lib/comissoes.ts` (tested), shared by every role's "Comissão" view via `ExtratoComissao`; master manual triggers and the frozen month are stored in master-only `simulado_imports` (tipo `comissao`/`comissao-fechado`) to avoid a new table, so restricted users see manual triggers as pending.
- Simulado (master-only tab): parsing/adjust rule in `src/lib/simulado.ts` (tested), imports only inside the tab, stored as JSON per source in `simulado_imports` (upsert by tipo+mes, Efetivo by year); adjusted expense = max(simulado|orçado, Efetivo last-5-months average, GNC SYS month-to-date) using only the marked cost centres.
- Controle O.S. manual status lives in `os_acompanhamento.acoes.__status` (with history) and wins only while newer than the latest weekly import (`comStatusManual`); NPS detractor follow-up reuses `os_acompanhamento` rows keyed `nps:<chassi>` (`acoes.__nps`) to avoid a new table.
- Technician 'sem apontamento' billing is stored as oficina_mes row `mes = "semapont-AAAA-MM"` (diario = {servicos,pecas}), same no-migration pattern as agenda rows. Unified-import undo restores only daily_sales/NPS/parts snapshots taken in-session before saving.
- NPS technician link is stored as oficina_mes row `mes = "tecchassi-AAAA-MM"` (diario = chassi → technicians of latest O.S.), written by the Passagens import; same no-migration pattern.
- "Faturamento de Peças" also feeds parts agregados (Tunap/Brazzo) via `agregadosDoFatPecas`, saving only the target month so a cumulative sheet never hits closed months.
- Item quantity display goes through `qtdItem`/`litrosDe` (`src/lib/pecas-itens.ts`), which detects ml-launched fluids by unit price below R$1; every item table must use it instead of formatting `qtd` directly.
- Marcos/Delmir (chefe_oficina/controlador) also get read-only SELECT on the management tabs' tables via `oficina_owner()` "oficina read" policies, so CockpitOficina's sidebar reuses the master Agregados/Mecanicos/ControleOS/Agendamentos/NpsPainel components unchanged; writes stay master/editor-only.
- Exception: Marcos/Delmir may INSERT/UPDATE `os_acompanhamento` (non-`nps:` rows) via "oficina insert/update" policies so they can change Controle O.S. status; user_id defaults to coalesce(data_owner(), oficina_owner()).
